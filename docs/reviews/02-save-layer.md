# 里程碑审查 2：保存层（src/ 全量，PR #2–#5 合并后）

- 方式：多 agent 冷启动审查（无上下文并行找缺陷 → 逐条验证 → 按严重度排序），强度 high
- 处理原则同审查 1：参数校验与边界问题直接修复并补回归测试；改变数据来源或语义的问题由我决定

## 影响设计的发现

| 发现 | 处理 |
|---|---|
| `strptime` 接受不补零写法（如 `2026-11-3 18:00`），可绕过 (账号, 时段) 唯一约束 | 时段与日期只接受补零的标准写法，模型调用与输入请求两处校验；回归测试用不补零写法抢占已占用时段，被拒 |
| 报告只读本次运行的记录，跨运行保留的草稿可能被报为"未保存" | 我决定：草稿信息一律读数据库最终状态（状态、时段、版本、是否占位），本次运行的操作结果单列为 `draft.this_run` |
| 守卫把执行失败的 `block` / `check_rules` 也计入 | 守卫只认执行成功的调用 |
| 同一轮中 `finish` 后还有调用时，后续调用未执行 | 拒绝非末位的 `finish`，其余调用照常执行 |
