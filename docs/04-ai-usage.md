# 04 AI 使用说明

## 1. 使用范围

| 用途 | 工具 | 说明 |
|---|---|---|
| 代码、测试、文档起草 | Claude Code（Claude Opus 5.5） | `src/`、`tests/`、`scripts/` 的实现由 AI 编写；文档由 AI 依据我的需求分析与设计决定起草，经我审阅 |
| 设计评审 | Claude Code 子 agent（3 个，冷启动） | 设计初稿完成后，分别从阅卷人、Agent 架构、工程与测试三个视角无上下文地挑毛病 |
| 代码审查 | Claude Code `/code-review`（多 agent 冷启动 → 验证 → 按严重度排序） | 两个里程碑各一次，记录见 [reviews/](reviews/) |
| 被测对象 | DeepSeek `deepseek-flash` | 产品本身的决策模型，不属于开发辅助 |

提交记录保留了 `Co-Authored-By: Claude` 署名，与本说明一致。

## 2. 工作方式

我负责方向与判断，AI 负责实现：

1. **需求分析与设计由我完成**，整理成初稿后交给 3 个冷启动 agent 从不同视角评审；我对比意见后逐条拍板，形成设计 v2。
2. **实现按"行走骨架 → 纵向切片"推进**，每个切片一个 PR，CI 强制通过；每个切片完成后我实际运行 CLI，看输出与 trace 是否符合预期，再决定合并。
3. **里程碑审查**：参照 Claude Code 官方 Code Review 的流程（并行找缺陷、逐条验证、按严重度排序、合并由人决定）。参数校验与边界类问题由 AI 直接修复并补回归测试；涉及确认边界、数据来源等语义的问题由我决定修法与时机。
4. **真实模型验证**：我阅读真实运行的 trace，对照需求判断决策是否合理，据此调整设计。

## 3. 我的决策

以下决定由我做出，AI 按决定实现：

**需求与范围**

- 选择项目题 1，范围取舍为"硬性底线全部满足但做薄，保存层（确认边界、防重复、并发、如实报告）做深"，因为高分依据与关键缺陷都落在这一层。
- 题目未说明发布方式。我判断：机器发布是秒级的，不存在"发不完"，冲突的真实来源是**同账号发布间隔**（流量互抢、平台频率检测），人工发布的操作耗时也折算进去；结合参考实例（18:00 被占 → 19:00）推定一个时段为一小时、同账号每时段一条（需求假设 A1、A2）。
- 审核分两层：固定字段校验交给程序，按"直接打回 / 可以补查 / 待补"三档；内容审核在业务信息不足时不扩展，只保留确定性词表。
- 题干"不得擅自改变硬性发布要求"有两种读法，我选择区分"指定时间"与"硬性要求"两级，并在方案中记录另一种读法。

**设计**

- 排期存在并发（两个流程同时审核、同时排期），且窗口内无空位时要打回并**附带占满的排期**；占用清单是客观事实，由程序在登记待确认项时自动附上，不依赖模型转述。
- 模型自报的 `needs_confirmation` 不能代表是否需要确认，必须结合"实际时段与要求时段是否一致"由程序判断。
- 推荐的替代时段必须经过程序校验，不能完全交给模型决定：读真实运行 trace 时发现模型把 18:00 改到了更早的 17:00，我决定加入"未给窗口时只能顺延"的程序守卫。
- 报告中的草稿信息以数据库最终状态为准，避免跨运行时把仍占位的草稿报成"未保存"。
- 第二轮确认（`--confirm`）在时间内不做，列为未完成，优先保证必须验收点与真实运行记录。

**开发方式**

- 先搭行走骨架、跑通链路再按验收点纵向切片；每片一个 PR，CI 强制 ruff + pytest。
- 借鉴 Claude Code 官方 Code Review 的多 agent 冷启动审查与按风险分级处理；里程碑审查而非每个 PR 都审，控制时间。
- 工具从简：只用 ruff 与 pytest，不引入 Agent 框架或额外的开发辅助插件。

## 4. 验证方式

- **每个切片**：运行 CLI，检查报告字段（审核状态、建议时段、待确认项、草稿状态、`publish_status`）与 trace（工具、参数、依据、返回、下一步）。
- **审查结论**：逐条核对问题是否成立、按风险分级决定处理；高风险项（不补零写法绕过唯一约束、报告采信模型标记）均有对应回归测试。
- **真实模型**：12 次运行逐条阅读 trace，确认每个验收点的实际行为（见 [03-evaluation](03-evaluation.md)）；发现的问题（替代时段提前、确认选项为快照）记入评估文档。
- **自动化**：75 项测试在 CI 上每个 PR 运行，全部通过。

## 5. 用时

约 3 小时，分多段完成。大致分配：需求分析与设计评审约 1 小时，实现与代码审查约 1.5 小时，真实模型运行与文档约 0.5 小时。
